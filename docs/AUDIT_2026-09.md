# 전체 감사 (2026-09) — 확정·미확정 목록

감사자 13명(영역별)이 코드를 적대적으로 읽고 재현 스크립트로 찔러 낸 원 발견 139건.
검증 에이전트는 세 번 다 세션 한도에 걸려, 이후는 사람이(이 세션에서 Claude 가) 코드를

## 감사 방법의 교훈

- 발견마다 검증자를 하나씩 두면 140명이 넘어 한도에 걸린다. 영역별로 묶어도 22명이었고 그것도 걸렸다.
  **다음엔 감사 → 사람이 대조 → 고치기** 순서로 처음부터 간다. 검증 에이전트는 상위 20건에만 쓴다.
- 감사자가 낸 139건 중 실제로 고친 것이 61건(일부 1건)이다. 나머지 대부분은 틀린 것이 아니라 **지금 고칠 조건이 안 되는 것**
  (전작 DB 실물, 번들 모델, Windows 실기)이다. 그 조건이 갖춰지는 날 이 문서를 다시 연다.
- 이번에 잡힌 것 중 가장 무거운 둘 — 설치본이 아예 안 켜지는 spec 진입점, 서재에 완독 표시가 없던 것 — 은
  둘 다 **테스트 385건이 통과하던 상태**였다. `python -m` 과 단위 테스트는 설치본과 사용자 동선을 보지 않는다.
